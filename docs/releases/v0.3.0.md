# Atlas of Threads - Bring your own Agent release

**Version 0.3.0 · September 8, 2026**

Bring the agents you already work with into your Personal Atlas. Let one build
the next path, let another walk beside you, and keep each contribution connected
to its origin. This release adds agent connections and private guide discussion,
a richer terrain to explore, and a complete cinematic soundtrack.

Version 0.3.0 is a feature release following 0.2.0. It remains a local-first
application for Windows and Linux; your existing Personal Atlas stays on your
machine.

## Bring your own agent

Atlas now includes a local **MCP Agent Bridge** and configuration guidance for
**Codex, Claude Code, Grok Build, OpenCode, Prime Agent, OpenClaw, and Hermes**.

- Read and search your Atlas from an agent, retrieve exact chambers, and ask for
  cited context without creating a graph.
- Explicitly grant a named collaborator permission to start a private Threadwalk
  or append an attributed path. Read-only is the default.
- Leave a question at an exact thought instead of losing its context in a
  separate conversation.
- Reconnect and retrieve the same stored IDs. Identical retries reuse existing
  receipts, protecting against duplicate contributions.
- Keep agent/provider attribution visible. Inbound contributions do not pretend
  Atlas executed a model it did not call.
- Generate client configuration with `mcp config` and verify the connection with
  `mcp check`. Windows includes the dedicated `AtlasOfThreadsMCP.exe` console
  host; Linux uses the installed Atlas executable.

MCP is one direction of connection. It does not, by itself, let Atlas call an
agent back or read its memory. Named Codex and OpenCode agents can separately
use return routes with resumable conversations and explicitly approved,
read-only memory-file projection. Memory candidates and acknowledgements keep
client-owned memory separate: an agent saves through its own mechanism, and
Atlas records an opaque acknowledgement rather than copying a vault.

[Connect your agent](https://github.com/MelaBuilt-AI/atlas-of-threads/blob/v0.3.0/docs/AGENT_ONBOARDING.md)
provides the complete setup and permission boundaries.

## Meet Agent Spark

A floating, illuminated companion now accompanies the Threadwalk. Click Spark
to open a private conversation about the thought where you are standing.
The circular interface keeps the conversation close to the scene, with your
question and the guide's reply visible together.

Choose **up to five collaborators and one independent guide**. The same agent
can take both roles, or your guide can be different from the agent generating
paths. Guide discussion is prose: it does not automatically create a graph,
write a Field Note, or turn its opinion into evidence. Its context follows the
selected thought, and role changes are clearly signaled.

Local guide support includes Claude Code, Codex, Grok Build, OpenCode and Prime
Agent. Existing Hermes and OpenClaw agents can serve through the explicit remote
connection. Provider authentication and model selection remain with those tools.

## Discover local agents and connect remote ones

Workspace setup now discovers supported local installations and offers a rescan.
Choose a discovered agent, check its health, and assign its role.

**Add Remote Agent** connects to one SSH destination you supply. Atlas verifies
the host key, discovers supported existing Hermes/OpenClaw agents, and registers
only the agent you choose after its health check. Connection guidance separates
host reachability, trust, authentication and agent readiness. Scoped firewall
instructions include undo steps; Atlas does not automatically change firewall
rules or scan the LAN.

Credentials and native memory remain on the agent host. The helper runs on a
POSIX host such as Linux, macOS or WSL. An optional private Unix-socket forward
supports inbound MCP; this is a private connection to your own Atlas, not the
future shared Atlas service.

## Walk a more tangible Atlas

- **Ten terrain textures** give Threadwalks their own atmosphere. Curved terrain
  carries warm traveled paths and cool generated destinations.
- **Reflect with R** turns the view toward your experienced route. Up/Enter
  retraces exact thoughts. R again returns to the chamber where reflection
  began, even if another answer arrives while you are looking back.
- **Back/Down enters Reflect** during ordinary navigation; Field Notes and
  Capsules retain their return-to-chamber behavior. The relic index moves to
  **Shift+R**.
- **Left and right include the center object.** Cycle through surrounding
  choices and back to the thought on which you arrived. Refocusing the center
  does not move you to another chamber.
- **Standing and selected thoughts are distinct.** Preview a destination before
  entering it, while retaining the place where you stand.
- **Atlas Map opens exact thoughts**, with an All answers view and a Thoughts in
  this answer view. Current and previously visited locations are marked.
- **Smoother chamber arrivals** prepare models and materials before revealing
  the scene. Route objects stream within a bounded resident window.
- **Reflect atmosphere** adds violet lighting and glowing neural forms, while
  shoulder and overhead views keep the route readable.
- **The Threadwalk title stays with the standing label.** The resume screen
  keeps its three choices: Resume Last Chamber, Open Session Head and Home.

All **33 cinematic sound effects** are integrated, including the newly supplied
cues for evidence, relics, cuts and vetoes, cancellation, Field Note eligibility,
and Agent Spark. The effects retain independent volume and pause controls.

Press **L** for the lightweight music and sound player:

- Pause music and effects separately and set their volumes independently.
- Skip backward or forward, or select a track directly.
- Let the album play through and loop.
- Load your own songs, a folder, or an M3U/M3U8/PLS playlist. Supply local songs
  alongside a playlist or in the selected folder so its references can resolve.
  Browser-playable HTTP(S) stream entries are supported too.
- Keep local music in your browser tab; Atlas does not upload it or add it to
  the graph store. Reloading restores the bundled album.

Fresh launches request the main title during onboarding and resume setup.
Starting a new Threadwalk or explicitly resuming one selects a random track,
avoiding an immediate repeat when the queue has multiple tracks. Ordinary
chamber movement continues the current song. Random entry respects a pause in
that tab and works with your custom queue. Volume persists; a music pause lasts
for that tab. If the browser blocks autoplay, the first click or keypress starts
the music. The resume screen offers a small **Press L for Music and Sound** note
below its original three tiles.

The player streams one track at a time. Byte-range audio serving supports correct
duration and seeking without decoding the whole album into memory.

## Reliability and packaging

- A collaborator response with invalid graph formatting gets **one bounded
  formatting-repair attempt** using the same request and collaborator. This does
  not retry transport errors, reopen old failures, or overwrite successful
  sibling continuations. A failed repair stays visible as a recorded failure.
- Packaged Linux launches restore the native library environment needed by
  external provider tools.
- Collaborator selection and pending guide changes are reflected consistently.
- Windows MCP uses UTF-8 standard streams and a dedicated console executable.
  Desktop assets are kept out of the console bridge to avoid bundling the visual
  and audio payload twice.
- Package checks cover the desktop UI, installed Windows MCP host, SSH dispatch,
  discovery, guide entry points, formatting repair, all cinematic audio files,
  and audio range responses.

## Upgrade or install

Existing installations can use **Workspace → Update Atlas** when the new release
appears. The updater downloads the exact platform package for the stable release
and verifies its SHA-256. Windows runs the installer; Linux replaces the binary
and restarts the application. Your Personal Atlas and provider configuration are
preserved.

- **Windows:** [Download AtlasOfThreadsSetup.exe](https://downloads.atlasofthreads.com/releases/v0.3.0/AtlasOfThreadsSetup.exe)
- **Linux:** run `curl -fsSL https://atlasofthreads.com/install.sh | sh`
- **Pinned Linux binary:** [v0.3.0 x86_64](https://downloads.atlasofthreads.com/releases/v0.3.0/atlas-of-threads-linux-x86_64)
- **Checksums:** [SHA256SUMS](https://downloads.atlasofthreads.com/releases/v0.3.0/SHA256SUMS)
- **Updated field guide:** [app.atlasofthreads.com](https://app.atlasofthreads.com)

Both packages are self-contained; no Python or Git installation is needed.
The Windows installer remains unsigned and may show a publisher/reputation
warning. Provider tools, authentication, account eligibility and usage charges
remain outside Atlas. Closing the browser does not quit the application; use
**Workspace → Quit Atlas**.

## What remains yours

Graphs and their attribution remain append-only. Human Field Notes and Knowledge
Capsules remain your interpretation, with their existing provenance and integrity
boundaries. There are no Atlas accounts, automatic graph uploads, cloud sync, or
shared-world publication in this release. Agent connections send the selected
context needed for your request to the tool you chose. The visible thought-graph
is the public structure of an answer, never a claim to expose hidden reasoning.

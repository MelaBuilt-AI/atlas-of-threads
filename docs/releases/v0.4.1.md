# Atlas of Threads — Security update

**Version 0.4.1 · October 3, 2026**

This update closes a gap in how the desktop app's local server checks where
requests come from. Every user of 0.4.0 should install it. Nothing else changes:
your Personal Atlas, your connected agents and your settings carry over as they
are.

## What was fixed

Atlas runs a small server on your own computer at `127.0.0.1:7462`, which the
Atlas window talks to. In 0.4.0, some of that server's actions accepted requests
without confirming they came from the Atlas window:

- **Another website open in your browser could start AI work in Atlas.** It
  could open a new inquiry, or continue an existing thread, on the provider you
  connected, using your subscription. It could also change your provider
  settings. It could not read the response, and provider calls run with tools
  disabled.
- **Another website could read your Personal Atlas** through a technique called
  DNS rebinding.

Recent versions of Chrome block websites from reaching local addresses. Firefox
and some other browsers do not.

In 0.4.1, every action must come from the Atlas window itself, and the server
refuses any request addressed to a name other than its local address. The Atlas
window already worked this way, so nothing changes in how you use it.

## If you script Atlas's local API

Requests that change anything now need `Content-Type: application/json`. Tools
such as `curl` must send that header explicitly:

```
curl -H 'Content-Type: application/json' -d '{...}' http://127.0.0.1:7462/api/...
```

Read-only requests are unchanged.

## Updating

When Atlas is open, it shows an **Atlas update available** notice with an
**Update Atlas** button. You can also install it fresh:

- **Windows:** [AtlasOfThreadsSetup.exe](https://downloads.atlasofthreads.com/releases/latest/AtlasOfThreadsSetup.exe)
- **Linux:** `curl -fsSL https://atlasofthreads.com/install.sh | sh`

The [0.4.0 release notes](v0.4.0.md) describe everything in the Connected Atlas.
